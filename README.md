# ChartLint

**電子カルテの医師記録に対する Linter** — ESLint がコードの問題を指摘するように、診療記録の「矛盾・抜け・古い情報」を検出するコンセプトのデモです。

🔗 **デモを見る: https://claude.ai/code/artifact/15574bef-1200-4755-8244-9c2278d99c8f**

---

## コンセプト

ChartLint は **診断を支援しません**。指摘するのは、医師自身が書いた記録の中の不整合だけです。

> ❌ 「低Na血症なので○○してください」（治療方針の提案）
> ✅ 「あなたが書いた Assessment と Plan が対応していませんよ」（記録の指摘）

この線引きによって、AI診断支援ではなく **documentation quality assurance（診療記録の品質保証）** として成立します。責任範囲が限定され、医師の主体性も保たれます。

そして、**書き換えは必ず医師の承認後**に行われます。ChartLint が勝手にカルテを書き直すことはありません。CodeRabbit がコードを書き換える前に「ここ怪しいですよ」とレビューするのと同じ関係です。

## デモの流れ

架空の症例（誤嚥性肺炎で入院5日目の78歳男性）の電子カルテ画面上で、以下を体験できます。

1. **「カルテをチェック」** をクリック → 経過記録がスキャンされる
2. **🔴 2 Errors / 🟡 3 Warnings** が検出され、指摘カードが並ぶ
3. カードをクリック → カルテ本文の該当箇所と、左の**根拠**（検査値・培養結果・処方・アレルギー欄）が連動してハイライト
4. 各カードの **修正案（diff 形式）** を確認し、「承認して適用」または「無視」
5. 承認すると**カルテ本文が実際に書き換わる**
6. 全件処理すると **All checks passed**

## 実装されているルール

| ID | 種別 | 検出内容 |
|---|---|---|
| CL-004 | 🔴 ERROR | 記録内矛盾 — O)「SpO2 96%（room air）」⇔ P)「酸素 2L/min 継続」 |
| CL-021 | 🔴 ERROR | アレルギー・処方矛盾 — ペニシリン系アレルギー ⇔ ABPC/SBT 継続 |
| CL-001 | 🟡 WARNING | Assessment に対応する Plan がない — 低カリウム血症（K 2.9） |
| CL-013 | 🟡 WARNING | 重要な検査値変化に言及なし — Cr 0.9 → 1.6 |
| CL-033 | 🟡 WARNING | 古い情報のコピー残存 —「喀痰培養結果待ち」（8/23 に結果確定済み） |

ルール体系としては、以下の5カテゴリ・約50ルールの構想があり、そこから「LLM だけで判定でき、かつデモ映えする」ものを抜き出しています。

- **A. 記録内部の矛盾** — 左右、肯定/否定、意識状態、呼吸状態、退院方針など
- **B. Assessment ↔ Plan の対応** — Problem に対する Plan の欠落、critical value の未対応など
- **C. 薬剤・アレルギー** — アレルギー薬の処方、開始理由の欠落、リスト間の不一致など
- **D. コピペ・古い情報** — 前日記録との類似度、解決済み事項の残存、時系列の破綻など
- **E. Problem list・引き継ぎ・退院** — 退院時 pending 検査、フォローアップ先の欠落など

## 使い方

```bash
open chartlint-demo.html
```

外部依存のない単一 HTML ファイルです（Web フォント以外の通信なし）。ブラウザで開くだけで動きます。

## 注意事項

- **これはデモ用モックです。** 患者・病院・診療記録はすべて架空のものです。
- **判定はハードコードされています。** 実際の LLM による解析は行っていません。デモを確実に動作させることを優先した設計です。
- 実運用を想定した安全性の検証・テストは行っていません。

## 背景

このプロジェクトは「プログラミングの Linter みたいに、電子カルテの医師記録をチェックしたら面白いのでは」という着想から出発しています。

関連する既存研究の領域としては、診療記録の品質評価尺度（PDQI-9）、copy/paste による情報の陳腐化と note bloat、problem list の整備を促す臨床意思決定支援（CDS）、退院時 pending 検査の記載漏れ、LLM による診療記録の自動監査などがあり、単なる思いつきではなく研究テーマとしても土台のある領域です。
